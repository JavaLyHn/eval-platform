# Skill 评测 / 优化 —— 生产就绪评估

> 日期:2026-06-10。范围:截至 M8(发版门)的 Skill 评测 / 优化能力。
> 配套:《Skill 评测 使用文档》`docs/skill-eval-使用文档.md`。
> 准则:本平台为 demo / 原型阶段,**如实评估,不把 demo 说成生产可用**。

## 一句话结论

**功能闭环是通的(M0–M8:评测 → 优化 → 留出对比 → 报告 → 发版决策),但不能对外正式开放使用。**
阻塞不在功能缺失,而在**安全、部署、并发、业务根本限制**几块仍是 demo 级。

## 完整度矩阵

| 维度 | 状态 | 说明 |
|---|---|---|
| 功能闭环 | ✅ 通 | 评测→优化→留出对比→报告→**发版门(校准/抽审/pass^k)** 全打通,380 前端测试绿,M8 已浏览器验收 |
| 黄金准则合规 | ✅ 好 | 判分 100% 确定性、无 LLM-judge 循环、pass^k 保下限、红线一票否决、人审是发版硬前提 |
| **被测对象** | ⚠️ 根本限制 | 评的是**自托管 target**(skill 当系统提示喂自配 LLM),**不是真 Platform 员工**——Platform 无写 / 绑定接口,真员工 skill 优化闭环 park。**这是业务价值的天花板** |
| **安全** | ❌ 阻塞 | ① **前端把 LLM apiKey 放请求体发后端**(密钥应后端托管,见 `skillopt-client.ts` 的 `llm:{baseUrl,apiKey,model}`);② 后端 `SERVER_TOKEN` 默认空 = **无鉴权开放**;③ CORS 是 dev 配置 |
| **部署** | ❌ 阻塞 | SkillOpt 是 **gitignore 的本地 clone + 独立 venv**(`eval-platform/SkillOpt/`),**没打进镜像**,后端靠 `skillopt_python` 硬路径起子进程;换机即「SkillOpt 未就位」。无可重现部署 |
| **并发 / 多用户** | ❌ 阻塞 | `mergeById` 整记录 local-wins → 跨设备并发审标注分叉;报告无行级隔离(`reportVisibleTo` 是**前端过滤**,后端返回全部);长任务子进程无队列 / 超时 / 并发上限治理 |
| 评分覆盖 | ◑ 部分 | 仅覆盖 A+B 确定性题(红线 / 超范围 / 带判分项);**C 类自由发挥题进不了评分**(需 LLM-judge,未做) |
| 数据 / 审计 | ◑ 部分 | 报告 PG 持久化 OK;无 RBAC、无操作审计日志、无合规导出 |
| 验收 | ◑ 部分 | M8 已浏览器验;**M3–M7「跑整轮 → 存报告」全链路尚未完整实点**(用 demo 报告只验了报告 / 发版决策侧) |

## 要「正式用」最少补齐(按优先级)

1. **安全收口**(最先):密钥后端托管(去掉前端传 key)+ 打开 `SERVER_TOKEN` 鉴权 + CORS 白名单收紧。
2. **可重现部署**:SkillOpt 打进镜像(Dockerfile 纳入 + 固定 python 路径),否则换环境跑不起来。
3. **长任务治理**:超时 / 并发上限 / 终止后清理 / 失败重试(现在长跑子进程裸奔)。
4. **多用户 / 并发**:`mergeById` 改字段级(修跨设备并发审分叉)+ 后端行级可见性 / 权限。
5. **Platform 写回接口**(业务根本):没有它,永远只能评自托管 target、不能真优化线上员工——**卡在 Platform 侧,不在本平台**。
6. **评分覆盖**:C 类自由题接 LLM-judge;把校准 / 抽审接进正式放量流程(不止单报告人审)。
7. **全链路浏览器验收 + 基本监控 / 告警**。

## 现在适合做什么

- ✅ **内部演示、方法论验证、试评一份 skill 的好坏 + 看自动优化能否提分 + 走发版决策流程**。
- ❌ 对外 / 多人正式生产、改线上员工、放进对客流程。

## 备注

- 上述「安全 / 部署」对应 memory 与 spec 里早已记的「下一步 ⑥ 部署化 = SkillOpt 打进镜像 + 后端密钥管理替前端传 key」;「并发」对应「下一步 ⑦ mergeById 字段级」;「评分覆盖」对应「下一步 ① C 类 LLM-judge」。
- 这些都是**已知项**,不是新发现的坑——属于「原型 → 生产」必经的工程化,不影响当前 demo 的方法论价值。
