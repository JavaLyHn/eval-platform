# Skill 评测 / 优化 —— 完整使用文档(零基础版)

> 面向第一次用的人。从「这是什么」到「跑完一轮并做发版决策」一步步走。
> 版本对应:截至 M8(发版门)。分支 `feat/skills-eval`。**当前为 demo / 原型,非生产可用**(生产差距见文末 + 单独评估)。

---

## 0. 一分钟搞懂这是什么

- **目的**:给一份「技能说明书」(`skill.md`,就是给 AI 的一段系统提示词)做**自动优化**——反复「试跑 → 反思 → 只收更好的改动」,并在**没见过的留出题**上对比优化前后,最后由人拍板能不能发版。
- **被测对象 = 「skill + 模型」的组合**(评 AI 要连它的提示词和模型一起评)。
- ⚠️ **重要前提**:这里被优化/被测的是**自托管 target**——把 skill 当系统提示喂给你配置的 LLM 跑。**不是直接改 Platform 线上员工**(Platform 目前只有「读 skill」接口,没有「写 / 绑定」接口,所以真员工的 skill 写回还做不了)。本工具现在的价值是:**评测一份 skill 好不好、自动找更好的写法、并给发版结论**。
- **判分 100% 确定性**(无泄漏红线 / 语言匹配 / 无占位符 / 工具成功 + 期望标签),**不用 AI 当裁判**——这是刻意的(避免「AI 评 AI」的循环造假)。

---

## 1. 跑起来之前(前置准备)

需要三个服务都在 + SkillOpt 引擎就位 + 一个 LLM 配置。

### 1.1 启动三件套
| 组件 | 默认地址 | 启动 |
|---|---|---|
| Postgres | `127.0.0.1:5433`(docker 容器 `agent-evaluator-db-1`) | `docker start agent-evaluator-db-1` |
| 后端 FastAPI | `127.0.0.1:18791` | `cd server && uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 18791` |
| 前端 Vite | `localhost:5173` | `npm run dev` |

> 仓库里有开发启动脚本(见 `docs/superpowers/{specs,plans}/2026-06-07-dev-startup-script*`),可一键起后端+前端;PG 用 docker 单独起。
> 健康检查:浏览器开 `http://127.0.0.1:18791/health` 应返回 `{"status":"ok"}`。

### 1.2 SkillOpt 引擎就位(关键,容易漏)
优化循环靠一个 Python 引擎 [microsoft/SkillOpt](https://github.com/microsoft/SkillOpt) 跑。它是 **gitignore 的本地 clone**(`eval-platform/SkillOpt/`),**不在主仓里**,需要本机已 clone 且装好它自己的 Python 虚拟环境。
- 后端按配置 `skillopt_root` / `skillopt_python` 去起子进程。**找不到就会报「SkillOpt 未就位:找不到 …」**。
- 换机 / 新环境第一次用,务必先确认这个 clone + venv 在位。

### 1.3 配一个 LLM(模型 Profile)
评测要真调一个 LLM。去主界面的**模型 / Profile 配置**处,新建一个 **LLM 类型 profile**,填:
- `baseUrl`(OpenAI 兼容网关地址)
- `apiKey`
- `model`(如 `claude-sonnet-4-6` / `gpt-5.2`)

> 网关地址带不带 `/v1` 都行——后端会自动补 `/v1`(早期「全题无响应 / tokens=0」就是网关少了 `/v1`,已自动修)。

## 2. 打开 Skill 评测页

左侧导航进 **「Skill 评测」**,或直接访问 `http://localhost:5173/skillopt`。

页面是**引导式单栏**:顶部一句话定位 + 5 阶段流程条(`基线 › 逐步优化 › 注入经验 › 留出评测 › 完成`);左栏是「题集」只读展示;右栏是配置 / 运行 / 结果。

---

## 3. 配置一轮评测(右栏配置卡)

### 3.1 选 LLM
从下拉里选你在 1.3 配好的 LLM profile。没有 profile 或缺 baseUrl/apiKey/model → 启动按钮不可用。

### 3.2 选「种子来源」(要优化的初始 skill)
- **内置中文客服种子** —— 现成的一份中文客服 skill,直接用。
- **从员工技能生成** —— 选一个 Platform 员工 + 它的某个技能,让 LLM 把该技能的英文描述**扩写成一份中文 skill**,你可以再编辑,然后拿它当种子。

### 3.3 选「题集来源」(拿哪套题去评 / 优化)
三选一:
- **内置题集** —— 固定的客服场景题,开箱即用。
- **该员工题集** —— 把某员工题库里「可确定性判分」的题(超范围 / 红线 / 带判分项的)自动按 ~5:2:3 切成 训练 / 选择 / 留出 三组。**必须 ≥9 题**才能跑,不够会禁用启动并提示去补对抗 / 红线题。
- **LLM 生成题集** —— 让所选 LLM 现给这份 skill 出一套题。
  - 出题时**一条一条流式冒出来**,可随时点**终止**(真的会中断在途请求)。
  - 出完进**人审关**:可改题面 / 切类型(拦截 vs 普通)/ 删 / 重新生成;留出集会标「LLM 生成,需人审通过才作发版依据」。
  - ⚠️ 黄金准则:**LLM 只负责出题,判分仍 100% 走确定性规则**,不让 AI 评分。

### 3.4 基础参数
- **epochs**(训练轮数):想看到「注入经验」效果至少填 **2**。
- **pass^k 的 K**:留出题每题跑 K 次、**K 次全过才算过**(保下限,面向客户用)。

### 3.5 高级参数(`▸` 折叠,留空=用默认,每项旁有 ⓘ 解释)
- **被测模型 / 优化器模型** —— 从已配 profile 下拉选,只换模型名、共用同一网关。
- **接受准则 gate** —— hard(严格全过)/ soft(部分给分)/ mixed(加权)。
- **更新模式** —— patch(增量改)/ rewrite(整篇重写)。
- **慢更新 / 元技能** —— 三态:默认随配置 / 强制开 / 强制关。

---

## 4. 启动 + 看运行中(实时)

点**「启动评测」**。右栏切到运行面板,三件套:
- **指标条** —— 5 阶段进度 + 「第 X/N 步」+ 总进度% + 本步通过率 + 选择集分数走势 sparkline + 收/弃/跳计数 + 已运行/阶段/静默计时。**静默 >90 秒会变黄预警**(通常是网关 / LLM 卡住)。
- **题块热力网格** —— 当前这批题逐题 绿(过)/ 红(挂)/ 灰(未跑),当前题脉冲,hover 看失败原因。
- **活动流** —— 把日志翻译成人话事件逐条冒出(基线 / 试跑通过率 / 收下·新最优 / 丢弃 / 注入经验 / 留出 pass^k …),原始 stdout 收进可折叠「技术日志」。

中途想停 → 点**终止**(真正杀掉子进程)。

---

## 5. 读结果(结果仪表盘)

跑完右栏出仪表盘,5 块:
- **结论条** —— 一句话总结(留出集质量分 基线→最优、通过几题、学到了啥)。
- **① 效果对比** —— 种子 vs 最优:通过率 hard% + 质量分 soft + 涨跌;留出集还有 **pass^k(K 次全过率)**。
- **② 优化过程时间线** —— 每步 接受 / 拒绝 / 无改动,可点开。
- **③ 学到了什么** —— 高亮「注入的经验」+ 折叠「种子 → 最优」逐行 diff。
- **④ 逐题表现** —— 每题 结果(保持 / 修好 / 变差)/ K 次通过 / 失败原因,可展开看模型回答。
- 底部「详细日志」折叠着原始 stdout。

---

## 6. 保存为报告

仪表盘上点**「保存为报告」**→ 填标题 → 存。这一轮会变成一份只读报告,**并入左侧「评测报告」列表**(和 Agent 评测报告并列,有「Skill / Agent」类型标签可筛)。报告**持久化到 Postgres + 跨设备 sync**(原始日志不入库)。点开走 `/skill-reports/:id`。

---

## 7. 在报告里做「发版决策」(M8 核心)

打开任一**带留出集**的 Skill 报告,仪表盘上方多两块:

### 7.1 发版结论卡
顶部一个大徽标给结论:**建议发版 / 谨慎 / 不建议 / 待人审**,下面列理由 + 三个信号小卡(留出 soft 涨跌 / pass^k 保下限 / 校准一致率)。

### 7.2 校准 / 抽审面板(人审)
逐道留出题列出:**题面 + 模型实际回复 + auto 判分(过/挂)+ 失败原因 + 是否红线**。你逐题判断「**auto 判得对不对**」,点 **「auto 对」/「auto 错」**,可加备注。
- 这一步就是「校准」——人核对**确定性判分器准不准**(抓误判 / 钻空子),不是再请一个 AI 来评。
- 顶部实时显示「已审 N/总数 · 一致 X%」。

### 7.3 发版门怎么判(瑞士奶酪硬门)
结论按这个顺序得出:
1. **没跑留出集** → 谨慎(无法判)。
2. **人审没过** → 封顶**「待人审」**,**无论分数多高都不给「建议发版」**。「没过」= 覆盖不够(没审满)/ 一致率低于门槛 / **红线(拦截)题被你判翻案**(红线一票否决)。
3. 人审过之后:留出回归 → 不建议;pass^k 跌(保下限掉了)→ 不建议;有提升 → **建议发版**;持平 → 谨慎。

### 7.4 门槛自己定
结论卡底部两个输入框:**一致率门槛 %** 和 **覆盖门槛 %**(默认 85 / 100),你按需改,改完即时重算。越界自动 clamp 到 0–100。门槛 + 标注都随报告存进 PG。

> 一句话:**分数只是参考,人审通过 + 保下限不跌,才给「建议发版」。**

## 8. 常见问题 / 排错

| 现象 | 原因 / 解决 |
|---|---|
| 启动按钮灰着点不了 | 没选 LLM profile,或 profile 缺 baseUrl/apiKey/model;或「该员工题集」不足 9 题 |
| 报「SkillOpt 未就位」 | 本机没有 SkillOpt clone / venv,见 1.2 |
| 全题无响应、tokens=0 | 网关问题;endpoint 缺 `/v1` 已自动补,若仍异常查 apiKey / 网关连通 |
| 指标条静默计时变黄(>90s) | 网关 / LLM 卡住,可终止重试 |
| 跑完留出集是「—」/ 无 pass^k | 这轮没跑留出集(题集来源 / 配置导致),报告里发版结论会显「谨慎(无法判)」|

---

## 9. 必须知道的边界(别误用)

1. **不是在改 Platform 线上员工**——优化的是自托管 target,真员工 skill 写回等 Platform 放开写接口。
2. **只有「可确定性判分」的题能进**(红线 / 超范围 / 带判分项)。开放式「自由发挥」题暂时进不了评分(需要接 LLM-judge,还没做)。
3. **跨设备并发人审有局限**——两台设备同时审同一份报告,标注可能各自为政(本地优先合并),目前别这么用。
4. **demo / 原型**:能演示、能内部试用,**不要当生产系统**。生产差距见《Skill 评测 生产就绪评估》。
