# QA Platform 使用文档(评测使用者版)

> 这是 Platform 6 位 AI 员工的**评测 / 上线决策平台**:给每位 AI 员工出题、让它答、给它打分,最后产出一份「能不能上线/放量」的报告。
> 本文只讲**基础操作**和**最重要的几个点**,看完就能上手。当前为原型阶段,结论供决策参考。

---

## 一、快速上手(5 步)

### 第 1 步:连上被测的 AI 员工(Agent)
左侧菜单 **Agent 管理** → 添加一个 Agent:
- 类型选 **platform**;
- 填 **instanceId**(被测员工的实例 ID,例如 Aria = `716567919089156096`,问平台管理员要);
- 保存后点**连接**,看到绿色「已连接」即可(右上角会显示连接状态)。

> API Key、platform 地址都在服务器后台,你**不用填密钥**,只填 instanceId。

### 第 2 步:配一个「裁判 / 出题」用的大模型
左侧 **LLM 管理** → 添加一个模型(OpenAI 兼容或 Anthropic,填好地址+Key)。
- 它有两个用途:**AI 出题** 和 **给答案打分(LLM 裁判)**。
- 裁判**必须**和被测员工不是同一个,平台会强制校验隔离。

### 第 3 步:出题(进题库)
左侧 **题库**:
- 可以手动加题;
- 也可以点 **AI 出题**:选维度(员工 / 行业 / 职业 / 场景,还能选某个 **skill** 专门出题)→ 开始生成。
  - 生成中可随时点**终止**,已生成的会作废。
- 每道题可标:**Pass 形态 / Fail 形态**、严重度(P0/P1/P2)、是否**超范围题**(用来测「该拒答的有没有拒答」)。

### 第 4 步:跑评测(让员工答 + 打分)
在 **评测中心**(会话)选好被测 Agent:
- 单题:直接发；
- 批量:选一批题一起跑(支持**多 trial**,见下方重点);
- 答完可**编辑 / 重发**某条消息。
- 打分:**确定性检查**自动跑(语言、泄漏、占位符、工具是否成功);需要主观判断的再用 **LLM 裁判**(可多裁判)。

### 第 5 步:看结果 + 出报告
- **数据看板**:通过率、平均分、成本、按员工/会话筛选、执行轨迹按轮查看。
- **评测报告** → 生成报告:
  - 选 **A 类(首版)** 或 **B 类(跟上一版对比)**;
  - 可选填各指标「目标值」;
  - 生成后看到 **§6 指标表 + 结论(能不能发版)**,可**导出 Markdown**。

## 二、重中之重(3 个一定要懂的点)

### ① 多 trial / pass^k —— 单次结果不算数,保下限看「每次都过」
AI 有随机性,跑一次过不代表稳。**面向客户、要保下限的题,开「多 trial(K 次)」**:同一道题跑 K 次,每次独立(互不串状态)。
看题目上的 **pass^k 角标**:
- 🟢 green = K 次**全过**(达标);
- 🟡 partial = 有过有挂(不稳,重点关注);
- ⚪ incomplete = 全过但没跑满 K 次;
- 🔴 red = 0 次过 / 没数据。

> 多 trial 会话**没有会话 ID(显示「未建立」)是正常的**——每次 trial 故意用全新隔离会话,不复用,这样才不串状态。答案、各次评分、角标都有,就说明真的跑了。

### ② 强约束红线 —— 一票否决,凌驾于一切分数
**只要有一道「安全红线」题失败,结论就是「不可发布」**,哪怕通过率、平均分再好看也没用。
报告页头和指标块都会显示 **✅ 可发布 / ⛔ 不可发布**。这是硬规矩,不能被平均分「拉回来」。

### ③ 评结果不评路径 + 失败要归因
- 不纠结员工「用了什么工具、什么顺序」,**只看结果对不对**(工具只查关键项有没有发生)。
- 每道**失败**的题会归到 **6 类原因**之一:知识 / 工具 / 参数 / 规划 / 风格 / 安全。归因是用来**诊断改进**的,不作为判分的硬路径。
- 还会标**不确定信号**(员工是否软化措辞 / 反问 / 拒答 / 自报置信度)——用来发现「表面答了其实没把握」的静默错误。

## 三、A/B 报告怎么读(刚上线)

报告在「逐题明细」上方多了一块 **§6 指标聚合**:

| 看什么 | 含义 |
|---|---|
| **通用 6 项** | 完成率 / 静默错误率 / 边界识别 / 一致性 / 满意度 / 红线。算得出的填实测,算不出的标 **N/A**;满意度标 **需人工**。 |
| **目标值列** | 你生成时填了才判达标/未达标;不填就只展示实测、不判(平台**不替你发明及格线**)。 |
| **专属指标** | 该员工角色相关维度的平均分。 |
| **结论** | 通过全量 / 限定通过 / 未通过。红线不过 → 一定「未通过」。 |
| **B 类差异表** | 跟你选的上一版报告逐项对比:↑ / ↓ / 持平,并给整体判定(提升 / 下降 / 持平 / 有升有降)。 |

> B 类需要先有一份带指标的 A 类报告作基线。

## 四、功能速查

| 在哪 | 能干嘛 |
|---|---|
| 评测中心 | 跟被测员工对话、单题/批量跑、多 trial、编辑重发 |
| 题库 | 加题 / AI 出题(可选 skill 维度、可终止)/ 标 Pass-Fail、严重度、超范围 |

| 数据看板 | 通过率/均分/成本、按员工筛选、执行轨迹按轮 |
| 评测报告 | 生成 A/B 报告、看指标与结论、导出 Markdown |
| Agent 管理 | 添加/连接被测 platform 员工(填 instanceId) |
| LLM 管理 | 配出题/裁判用的大模型(须与被测隔离) |

## 五、常见疑问

- **多 trial 没有会话 ID,正常吗?** 正常,见上方重点①(隔离设计)。
- **某个指标显示 N/A?** 说明这批题里没有对应数据:没有超范围题→边界识别 N/A;没跑多 trial→一致性 N/A;满意度恒为「需人工」。
- **报告结论是「未通过」但分数不低?** 多半触发了**安全红线**(重点②),红线一票否决。
- **专属指标名字看着像通用维度?** 当前用裁判实际打分的维度名,正确可读;不影响数值。
